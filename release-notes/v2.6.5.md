> **阿里 223.5.5.5（IP 直连）仍是保底**。

## 2. requestGate 闸门语义错误（真正病根，更隐蔽）

原实现：

```
await requestGate.WaitAsync();   // 占槽位
await httpClient.SendAsync();    // 等满 12s
requestGate.Release();           // 才释放
```

闸门覆盖了**整个网络等待期**。而闸门是全局共享的（容量 8），
慢端点一旦进入就占住 1 个槽位长达 12 秒。冷启动时 15 个域名 × 5 个端点抢 8 个槽位，
**连 148ms 就能返回的阿里端点也被排在门外干等** —— 这才是 32 秒的直接成因，
端点列表问题只是让它更容易触发。

并发突发恰恰发生在**发起请求的那一刻**，不在等待期间。改为只在发起瞬间持锁：

```
await requestGate.WaitAsync();
var request = new HttpRequestMessage(...);   // 构造
requestGate.Release();                       // 立即释放，不等网络
await httpClient.SendAsync(request, ...);    // 等待不再占槽位
```

容量 8 → 12（5 端点 × 2 记录类型 = 10 在途，12 刚好容得下"一次完整竞速"，
不至于让 A 与 AAAA 两轮串行）。效果：在途连接数始终 ≤ 12（跨境端点全挂时不会堆积
150 个连接），同时快端点永远不必排在慢端点后面等槽位。
