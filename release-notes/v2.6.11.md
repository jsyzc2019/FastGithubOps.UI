# FastGithubOps.UI v2.6.11

对照上游 [yuan71058/FastGithub v2.3.2](https://github.com/yuan71058/FastGithub) 全仓比对后，吸收 4 项独立改进（详见 `docs/上游对照报告-v2.3.2.md`）。

## 修复

- **「更新IP」不再会被中途打断**（借鉴上游，修复本仓库真实缺陷）
  此前 `/refresh-ip` 绑定请求生命周期且 UI 超时仅 10 秒：手动刷新是"清缓存 → 拉在线hosts源 → 全量重测速"，一旦超过 10 秒 UI 断开会把刷新拦腰砍断，系统停在"旧缓存已失效、新结果未就绪"的半刷新态，比不刷新更糟。
  现在后端用独立 45 秒预算驱动刷新（UI 断不断，刷新都完整走完）；UI 超时放宽到 60 秒，3 秒未完成先弹"进行中"提示。
- **「更新IP」返回真实结果**
  此后刷新完成会提示"IP更新完成：N 个域名、M 个可用IP（在线hosts源 X 个域名）"，失败时给出原因；不再永远只说"已发送请求"。后端为旧版本时自动兼容。

## 改进

- **hosts 源支持 JSON 格式**（借鉴上游）
  上游默认源已切换为 `https://raw.hellogithub.com/hosts.json`（`[["ip","domain"],...]` 数组）。现按内容自动识别格式（`[`/`{` 开头走 JSON，否则走原文本 hosts 格式），源格式迁移不再导致 hosts 通道静默失效。JSON 分支同样经过无效 IP 过滤（环回/内网/污染段），与文本格式同一套防护。
- **UI 全局异常兜底**（借鉴上游）
  上游实证故障链：日志页右键复制时剪贴板被其它进程占用 → COMException → 托盘进程崩溃 → 后端随父进程退出 → 加速静默失效。现未处理异常一律吞掉继续运行；剪贴板复制增加 3 次重试（间隔 100ms）。
- **CI/CD 修复并激活**（26 次连败的根因解决）
  仓库 NuGet.config 只配华为云镜像，该镜像在 GitHub runner 上 nupkg 下载损坏，是 2026-10 全部 26 次 Actions 失败的唯一根因。现 CI 内临时覆盖为 nuget.org（不影响本机 restore）。同时：
  - build.yml 增加 `--SelfTest` 冒烟步骤（13+ 条健康度/熔断断言）与手动触发；
  - release.yml 发布说明优先读取仓库内 `release-notes/<tag>.md`（单一事实来源）。

## 升级方式

下载 `fastgithub-win-x64-v211.zip`，解压后先退出旧版（托盘菜单「关闭应用」），再运行 `FastGithub.UI.exe`。配置文件（appsettings*）无需改动。
