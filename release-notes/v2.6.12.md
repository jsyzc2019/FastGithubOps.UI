# FastGithubOps.UI v2.6.12

落实《生态调研》（`docs/生态调研-可借鉴点-20261031.md`）的 B1 + B2 两项改进。

## 新增

### 官方 meta 段候选池扩充（B1）

**直击"候选池=1"痛点。** v2.6.9 审计确认：GitHub 权威 DNS 对 github.com 常态只回 1 条 A 记录，该 IP 一旦被阻断整个域名瞬时不可用。

GitHub 官方通过 `api.github.com/meta` 公开 web/api/git 等 CIDR 段（本项目已实测验证已知 github.com 真实 IP 全部落在 web 段内）。现在：

- 解析 `github.com` 系域名（`api.github.com` 用 api 段）时，从官方段自动采样最多 6 个补充候选；
- 采样避开已有候选、跨段轮转保证多样性、每轮随种子变化以覆盖不同入口；
- 采样候选与 DNS 候选走**同一套 TCP 握手竞速 + 健康度筛选**，不可用的自然淘汰；
- meta 数据缓存 24 小时，拉取走自家 DoH 链（ConnectCallback 复用 DnsClient），不走已被 RST 的系统 DNS；
- 拉取失败保留旧段、1 小时退避重试，采样路径任何异常都不影响主解析链路；
- 可用 `FastGithub:MetaCandidateExpand: false` 关闭。

### hosts 源多源 failover（B2）

`FastGithub:HostsUrl`（单源）升级为 `FastGithub:HostsUrls`（数组，按序 failover），默认三源：

1. `https://raw.hellogithub.com/hosts.json`（原单源）
2. `https://raw.githubusercontent.com/521xueweihan/GitHub520/main/hosts`
3. `https://gitlab.com/ineo6/hosts/-/raw/master/next-hosts`

第一个给出有效内容的源获胜，全部失败才计入失败退避；单源损坏不再让 hosts 通道瘫痪。旧的单源配置 `HostsUrl` 仍然兼容（未配置 HostsUrls 时生效）。刷新结果新增 `HostsSource` 字段标识实际命中的源。

## 自检

新增 `MetaRangeSelfTest`（CIDR 解析与归属、非法输入拒绝、域名→段类型映射、采样上限/去重/避开已有/确定性/多样性、meta JSON 解析容错）并注册进 `--SelfTest`，全部通过。

## 升级方式

下载 zip 解压，先从托盘退出旧版，再运行 `FastGithub.UI.exe`。配置无需改动；如需自定义 hosts 源，在 `appsettings.json` 的 `FastGithub:HostsUrls` 数组中配置。
