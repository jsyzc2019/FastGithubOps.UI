# FastGithubOps.UI v2.6.13

对照上游 [yuan71058/FastGithub v2.6.0](https://github.com/yuan71058/FastGithub)（v2.3.2 → v2.6.0 共 15 个提交）做全仓比对，并用本仓 8 天实际运行日志（10-21~10-28）验证后，落实 4 项实质改进 + 2 项低成本增强。详见 `docs/上游对照与日志分析-20261115.md`。

## 核心：慢性 DNS 噪音的根因修正（A1）

本仓日志实测：DoH 解析失败率 **15~22%/天**、「所有端点均不可用」**约 1000 次/天**、明文 DNS(TCP:53) 被 RST **约 1500 次/天**，且全天均匀、无时间聚集、无 ERR。上游 v2.5.0 用完全相同的现象描述定位根因并修复：**后台测速周期 1 秒等于每秒对全部域名×全部候选 IP 做一轮探测，把出口带宽与 DNS 配额打满，反过来挤掉真实请求**。本仓 `testPeriodTimeSpan` 正是 1 秒。

- 测速周期 **1 秒 → 60 秒**（提为 `TEST_PERIOD_SECONDS` 常量并加自检下界断言防回退）
- 故障恢复不依赖轮询：`ReportFailure → RefreshAsync` 仍即时触发重选（10 秒冷却）；DoH 正缓存 10 分钟、探测缓存 5 分钟，高频重测本就拿不到新结论
- hosts 源刷新周期（1 小时）独立于测速周期，不受影响
- 预期可复测：上述三项慢性噪音应下降一个数量级，且代理请求耗时/错误率不劣化

## 修复：候选池塌缩与页面转圈（A2/A4）

- **合并而非覆盖**：刷新时新探测结果优先、旧候选去重追加（上限 8）。上游 v2.4.2 实证「刷新直接覆盖旧候选，探测抖动只选出 1 个 IP 时候选池塌缩为单点，更新 IP 后反而打不开」；本仓日志中候选池=1 占 5~7%
- **成功 IP 记忆**：连接成功即把该 IP 提到候选首位，后续并发请求直接命中，不再逐个试错（上游 v2.4.4 修「页面一直转圈」）

## 修复：TLS 证书链错误被误放行（A3）

`TlsIgnoreNameMismatch` 分支原先直接 `return true`，连带放行了「名称不匹配 + 证书链错误」组合——污染 IP 背后的中间人正是这个特征，会凭响应快占据候选头部、真实请求却收不到数据。现在**证书链错误一律拒绝**，忽略配置的语义只覆盖「名称不匹配」。抽出纯函数 `IsCertificateAcceptable` 供自检钉死。

## 健壮性（B1/B2）

- **`/refresh-ip` 软超时**：45 秒预算耗尽返回 `{ timedOut: true, ... }` 且刷新在后台继续，不再取消任务、不再返回 HTTP 500；UI 提示「IP更新部分完成（后台继续刷新中）」
- **UI 未处理异常落盘** `logs/ui-error.log`：v2.6.11 的全局兜底此前只吞异常，双击没反应时完全无线索

## 自检

新增 `CandidatePolicySelfTest`（测速周期下界、合并不塌缩/去重/上限、成功 IP 置顶与未知 IP）与 `TlsPolicySelfTest`（含「名称不匹配+链错误」两条关键回归），注册进 `--SelfTest`，全绿。

## 明确不借鉴（记录在案）

上游 v2.6.0 端口策略（2000/3000 起）：本仓 `GetAvailableTcpPort` 已自动顺延，8 天日志零端口占用故障；内置候选池 9 域名/hosts 双源合并/DNS 服务器级熔断：本仓已有 meta 官方段扩充、三源 failover、10 分钟假可达冷却，机制等价或更强；TCP+TLS 双段探测/Happy Eyeballs/设置页：与健康度闭环重叠或属 UI 产品化，暂缓。

## 升级方式

下载 zip 解压，先从托盘退出旧版，再运行 `FastGithub.UI.exe`。配置无需改动。
