FastGithub × dev-sidecar 对比研究与优化报告

基线：yuan71058/FastGithub v2.3.1（.NET，透明拦截）　·　参照：docmirror/dev-sidecar（Electron + mitmproxy，系统代理）
产出：优化版 FastGithub v2.4.0 + win-x64 自包含单文件可执行程序　·　2026-10-02

一、结论摘要

两个项目解决的是同一个问题（国内访问 GitHub 等境外站点慢/不通），但走的是两条技术路线， 各自的短板恰好能被对方的强项补上：

  • FastGithub 强在"透明"：DNS 劫持 + 反向代理，应用零配置；但不具备"失败反馈闭环"， 一旦某个 IP 被判定为快，即使它后来连不通了，也会在缓存期内被持续优先选中 —— 这是"装了却没效果"的主因。
  • dev-sidecar 强在"反馈"：DynamicChoice 持续统计每个 IP 的成功率与连续失败次数， 命中阈值立即拉黑换下一个；但它依赖系统代理 + Electron，透明性和资源占用不如 FastGithub。

本次以 yuan71058/FastGithub 为基座，把 dev-sidecar 的"IP 健康度反馈闭环""污染地址过滤" "系统代理兜底"三块能力移植进来，同时保留 FastGithub 的透明拦截、轻量、无需逐应用配置的优势。 已产出可运行版本并通过启动冒烟验证。

二、架构对比

FastGithub（yuan71058 版）

WinDivert 驱动→ 拦截 UDP:53→ 命中域名返回 127.0.0.1→ Kestrel 监听 80/443/22/9418→ 自签 CA 做 TLS 中间人 + YARP 反向代理

非 Windows 平台退化为 127.0.0.1:38457 正向代理。

dev-sidecar

gui（Electron + Vue3）→ core（编排）→ fork mitmproxy 子进程 31180/31181→ 设置系统代理→ node-forge 伪造证书（LRU 缓存）

插件体系（git / node / pip / overwall）、多 provider DNS（UDP/TCP/DoH/DoT/预置 IP）。

四、诊断：为什么原版"装了没效果"

症状
启动正常、日志正常，但访问 GitHub 依然超时或极慢
根因 1
IPAddressService.GetAddressElapsedAsync 只测 TCP 握手耗时。在 TLS 层被阻断/重置的场景下，TCP 握手照样成功，坏 IP 因此被测速逻辑判定为"快"
根因 2
HttpClientHandler.ConnectCallback 的 catch 块只做 innerExceptions.Add(ex)，没有把失败回写给解析器，坏 IP 在 5 分钟缓存期内被反复选中
根因 3
DnsClient.LookupCoreAsync 只过滤 loopback。国内 DNS 返回的污染地址往往"握手很快"，会稳定进入首选队列并稳定失败
根因 4
WinDivert 一旦加载失败，Dns/TcpInterceptHostedService 直接 host.StopAsync()，程序整体退出

六、刻意未采纳的部分

dev-sidecar 能力为何不移植
preSetIpList 硬编码已知可用 IP数据是静态的，GitHub CDN 段会轮换，过期后反而变成"稳定失败"的来源；FastGithub 已有在线 hosts 源做等价且可更新的事
插件体系（git/npm/pip 自动配置代理）透明拦截模式下不需要逐工具配置；可作为后续可选增强，但不进入本次交付
Electron GUI 与多 provider DNS 全量实现体积与复杂度代价大；FastGithub 的 dnscrypt-proxy 已覆盖 DoH 场景

八、运行说明

  • 正常用法：以管理员身份运行 fastgithub.exe。透明拦截（DNS 劫持）需要管理员权限与 WinDivert 驱动。
  • 降级用法：若驱动被杀软拦截或不想用管理员权限，程序仍会监听 127.0.0.1:38457， 手动把系统代理设为该地址即可继续使用（这是本次新增的兜底通道，原版此时会直接退出）。
  • 服务模式：fastgithub start / fastgithub stop 安装与卸载 Windows 服务。
  • 手动刷新 IP：访问 http://127.0.0.1:38456/refresh-ip（UI 端口）可触发 IP 重选。
  • 证书：首次启动会在 cacert/ 生成自签 CA 并尝试装入「受信任的根证书颁发机构」； 若未以管理员运行会失败并提示手动安装。

九、后续建议

  • 把健康度指标暴露到 UI/日志：当前只在内部生效，建议让 /flowStatistics 一并返回各 IP 的成功率，便于排查。
  • 测速加入 TLS 层验证：目前测速仍是纯 TCP。可在 IPAddressService 中对 443 端口补一次带 SNI 的 TLS 握手探测，进一步压缩"能连不能用"的 IP 生存空间。
  • 健康度参数可配置：KeepErrorThreshold / MinSuccessRate / BlacklistDuration 目前是硬编码默认值，建议下沉到 appsettings.json。
  • 清理 net10 过时 API 告警：X509Certificate2(string/byte[]) 构造已过时，应改用 X509CertificateLoader。
