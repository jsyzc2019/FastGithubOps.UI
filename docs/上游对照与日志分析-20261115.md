## 一、上游 v2.3.2 → v2.6.0 做了什么

| 版本 | 主题 | 关键改动 |
|---|---|---|
| v2.4.0 | 间歇性打不开 | IP 可用性判定 TCP → **TCP+TLS 双段探测**；请求失败 IP 熔断 90s；内置候选池 4 域名；单 IP 超时 10→4s |
| v2.4.1 | 更新IP 提示取消 | 刷新**软超时**（预算耗尽返回已完成结果，剩余后台继续，不再 500）；**DNS 服务器级熔断**（连续 3 次失败停 5 分钟）；探测为空保留原 IP；测速并发 8→12 |
| v2.4.2 | 更新IP 后反而打不开 | 根因：hosts 源只给 1 个 IP 就 `yield break` 跳过内置池；**刷新直接覆盖旧候选**；`ReportFailure` 删光候选。修复：hosts 分支合并内置池、**新旧候选合并（上限 8）**、共用 7s 连接预算 |
| v2.4.3 | 检测更新入口 | 跳 Gitee 发行版页 |
| v2.4.4 | 页面转圈 | **成功 IP 记忆**（`ReportSuccess` 置顶）；单 IP 超时 4→2s；总预算 7→4s |
| v2.5.0 | 时好时坏（关键） | **后台测速周期 1s → 60s**（原值每秒对全部域名×全部候选 IP 做 TCP+TLS 握手，把出口带宽和 DNS 配额打满，挤掉真实请求）；测速拒绝证书链错误；Happy Eyeballs 阶梯并行；内置池 9 域名；hosts 双源并行合并；已验证 IP 落盘；设置页/问答页；UI 异常写 `logs/ui-error.log` |
| v2.6.0 | 端口策略 | Windows 不再绑定 80/443/22，改 2000/3000 起自动顺延；WinDivert 透明改写回环流量；Linux/macOS 不变 |

## 二、本仓运行日志实证（8 天，v2.6.10 运行期）

| 指标 | 实测 | 定性 |
|---|---|---|
| DoH 解析失败率 | **15~22%/天**（972~1326 次） | 慢性、全天均匀（每小时 21~93 次），非突发 |
| "所有端点均不可用" | **~1000/天** | 与上游 v2.5.0 描述的「公共 DNS 连续查询失败被熔断」同型 |
| 明文 DNS(TCP:53) 被 RST | **~1400~1600/天** | 均匀，之前定性为环境干扰 |
| DomainResolver 解析行 | **2.4~2.8 万行/天 ≈ 1000/小时** | 后台测速每轮持续产出，压力恒定 |
| 监听端口 | 22/80/443/9418/38457，**端口占用提示 0 次** | 本仓已有 `GetAvailableTcpPort` 顺延，端口冲突非痛点 |
| 代理请求 | 5~65/天，多数 0 错误，偶发 6~10%（小样本） | 用户实际流量很小 |
| 候选池=1 | 5~7% 解析行 | 单 IP 域名仍存在 |
| ERR/FTL | 0 | 无程序级故障 |

**关键修正**：此前把 DoH 失败/:53 RST 全部归为「环境干扰」。对照上游 v2.5.0 的根因说明后应修正为——
本仓 `testPeriodTimeSpan = 1 秒`，与上游被判定为「自造压力」的原值**完全相同**；
日志中「全天均匀、无时间聚集、无 ERR」正是持续自造负载的特征，而非纯外部波动。
即：**这部分慢性噪音至少有大半是我们自己每秒一轮的全量测速打出来的**。

## 三、可借鉴清单（A 级 = 本仓实证对应，B 级 = 低成本增强，C 级 = 不借鉴）

### A 级：直接对应本仓代码缺陷 / 日志实证

| # | 上游做法 | 本仓现状 | 依据 |
|---|---|---|---|
| A1 | 测速周期 60s | **1s** | 日志 DoH 失败 15~22%、全端点不可用 1000+/天、解析行 1000/小时 |
| A2 | 刷新合并新旧候选（上限 8） | `dnsEndPointAddress[...] = newAddresses` **直接覆盖** | 上游 v2.4.2 根因二；本仓库=1 占 5~7%，点「更新IP」后可能塌缩为单点 |
| A3 | `TlsIgnoreNameMismatch` 分支**拒绝证书链错误** | `if (NameMismatch && Ignore) return true` **放行任意链错误** | 污染 IP/中间人可凭响应快被信任；上游 v2.5.0 明确修复 |
| A4 | 成功 IP 记忆（`ReportSuccess` 置顶） | `ReportSuccess` 只清健康度惩罚，**不置顶** | 上游 v2.4.4 修「每个新连接从头逐个试候选 IP」导致页面转圈 |

### B 级：低成本、可诊断性/健壮性增强

| # | 上游做法 | 本仓现状 |
|---|---|---|
| B1 | 刷新软超时（预算耗尽返回 `timedOut` JSON，后台继续，不 500） | v2.6.11 用独立 45s CTS，超时会抛 `OperationCanceledException` → 500 |
| B2 | UI 未处理异常写 `logs/ui-error.log` | v2.6.11 有全局兜底但只 `Handled = true`，无落盘，「双击没反应」无线索 |

### C 级：明确不借鉴

| 上游做法 | 理由 |
|---|---|
| 端口 2000/3000 起（v2.6.0） | 本仓 `GetAvailableTcpPort` 已自动顺延，日志**零**端口占用故障；改高位需同步改 WinDivert 回环改写规则，风险大收益无实证 |
| 内置候选池 9 域名 / hosts 双源并行合并 | 本仓 v2.6.12 已有 **meta 官方 CIDR 段扩充**（覆盖更全）+ **三源 failover**，更强 |
| DNS 服务器级熔断（v2.4.1） | 本仓 `plainDnsBrokenCooldown` 10 分钟「假可达」冷却，机制等价且更久 |
| TCP+TLS 双段探测（v2.4.0） | 本仓刻意只做 TCP 握手（避免每候选一次 TLS 会话的探测风暴），真实请求阶段由 `IpHealthTracker` 拉黑坏 IP；A1 降频后更无需加回 |
| Happy Eyeballs 阶梯并行（v2.5.0） | 与健康度排序+串行首命中机制重叠，改动大；待 A 级实测后再评估 |
| 设置页/问答页/Gitee 更新入口 | UI 产品化，用户偏好少改 UI，与可靠性主线无关 |
